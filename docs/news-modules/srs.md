# 可选新闻模块软件需求规格说明（Software Requirements Specification，SRS）

状态：已确认需求，实施中；尚未完成运行验收。

来源：主人已确认完整可选新闻模块架构、可信模块批准后执行、外部运营 RSSHub、中文完整设计与小档测试计划；随后以“支持，推荐 搞定在pr 上去”确认首版支持 RSSHub 服务访问密钥并采用推荐方案实施、提交与推送到现有 Draft PR #1767。此授权不包含合并 PR、发布版本或托管 RSSHub。

研究依据：[可选新闻模块完整落地研究](../../plans/news-module-injection-research.md)。研究材料尾部已追加当前实施授权与文件级工作分解；此前独立核查只证明研究版本就绪，不能替代实现与运行验收。

关联待审产物：[软件设计说明](sdd.md)、[测试计划](test-plan.md)。三份文件分别审阅，不互相代替批准。

## 问题

主人希望非标准化新闻来源先抽象成模块，再以可选模块注入，后续社区化维护；避免第一方为每个网站增加独立采集旁路并承担持续维护责任。RSSHub 是优先复用的社区来源生态，不是必须随 Alice 托管的服务。

当前来源管理支持标准 feed、RSSHub 实例与显式 route、编辑和采集状态，但没有形成社区模块发现、批准、加载与执行闭环。当前来源管理 Draft #1767 不能代表本架构完成；#1647 的直接来源适配方案也不自动并入本事项。此判断来自研究所核查的候选提交，不是新发现的线上故障。

本轮没有提供目标用户数量、维护工时损失或商业效益数字，不补造量化收益。目标读者为后续维护者、实施者和社区模块作者。

## 方案

保留标准 RSS 能力；通过一个可选通用生产者读取用户或运营者提供的 RSSHub HTTP 实例；真正的非 RSS 来源由明确批准的社区模块负责抓取与转换。所有结果进入唯一核心校验和归档管线。可执行社区模块使用独立工作进程隔离故障，但不承诺 OS 级安全沙箱。

模块的发现、导入、批准、启用、更新、停用与卸载形成完整闭环，用户原有订阅与历史保持兼容。源码、桌面、编译命令行和远程后台的支持声明分别以实际运行证据验收。

## 场景

1. 维护者新增 RSSHub 已有 route：只配置通用接入，不新增站点专用第一方采集路径。对应 D2、D4。
2. 社区作者提供非 RSS 来源模块：用户批准后，仓库外制品实际采集数据，结果进入既有归档及界面；无需修改核心源码。对应 D3、D5。
3. 用户查看或导入模块但没有批准执行：模块代码不因列表展示被运行。对应 D5、D7。
4. 一个模块卡死或崩溃：它不可继续冒充正常采集，其他来源及聊天保持可用。对应 D6、D11。
5. 用户更新、停用或卸载来源模块：结果可核实，旧订阅与历史不被删除或重复导入。对应 D8、D9、D10。
6. 用户通过远程界面操作：制品和采集在后台执行，浏览器断开重连读取后台真实状态。对应 D13。

这些是由已确认目标导出的验收场景，不声称已在新实现中观测到。

## 定下的事

下列 D 项来自已确认的需求收口。接口具体签名、参数限额和切换顺序是设计说明中的待审提案，不借本节写成已批准实现。

### D1 标准来源

- 要求：没有启用社区模块时，普通 RSS/Atom 来源仍可通过标准管线采集。
- 依据：主人确认保留普通 RSS，并与其他生产者共用管线。
- 例子：社区模块未启用，标准 feed 返回合法条目 → 按标准能力采集；模块不可用 → 不能因此使其他标准来源失效。

### D2 RSSHub 接入与服务归属

- 要求：RSSHub 由可选通用生产者接入用户或运营者提供的 HTTP 实例，不逐 route 新增第一方采集脚本。
- 依据：主人选择外部实例，确认 RSSHub 优先和避免逐站旁路。
- 例子：实例 A 的显式 route 改为实例 B → 后台读取 B 的 feed；普通绝对 RSS URL → 不因 RSSHub 实例变化而改写。后者为现有已核查合同，须兼容。

### D3 仓库外非 RSS 模块

- 要求：可信社区制品经批准后能够适配真实非 RSS 来源，无须修改核心源码。
- 依据：主人确认真正非 RSS 来源仍可由社区模块适配。
- 例子：独立制品读取受控 JSON 新闻输入 → 经转换进入核心归档；只增加来源名称或回显 manifest → 不算满足要求。

### D4 唯一核心管线

- 要求：生产者结果共用核心校验、去重、归档、标签、保留策略、事件与健康管线。
- 依据：已确认需求收口。
- 例子：同一模块重复返回同一已归档条目 → 核心去重；来源模块自己写另一份归档 → 不符合统一管线要求。

### D5 执行批准

- 要求：可执行社区代码必须经用户明确批准，批准绑定具体版本与内容身份。
- 依据：主人选择“可信模块批准后执行”；该选项明确版本和内容身份。
- 例子：制品与批准身份一致且启用 → 可以进入加载流程；内容或版本变更、没有相应批准 → 不执行新代码。哈希只证明完整性，不证明作者可信。

### D6 故障隔离

- 要求：可执行模块使用独立工作进程隔离卡死和崩溃，不因单模块失败使其他新闻来源或聊天不可用；此工作进程不是 OS 沙箱，不提供内存硬配额。
- 依据：已确认执行边界及需求收口。获准代码仍以 Alice 后台 OS 用户权限运行。
- 例子：模块无限循环或异常退出 → 报告该模块故障，其他来源可采集；模块失控耗尽后台内存仍可能影响整进程，不属于已承诺隔离保证。

### D7 发现与导入

- 要求：模块发现、列表与导入不替代执行批准。
- 依据：D5 与主人确认的完整模块生命周期。
- 例子：读取未批准模块清单 → 只显示声明元数据、不执行入口；批准后启动 → 才允许执行已批准入口。导入入口的制品格式见设计提案。

### D8 生命周期

- 要求：模块支持导入、批准、启用、更新、停用和卸载，操作结果能够核实。
- 依据：已确认收口范围。
- 例子：进程已确认结束 → 停用可完成；进程树无法结束 → 显示失败，不能仅把按钮或配置改成关闭便声称已停用。具体提交与恢复契约见设计提案。

### D9 历史读取

- 要求：停用和卸载模块保留订阅配置与已有归档。
- 依据：已确认“保留旧订阅与历史兼容性”，及研究核查的独立归档读取能力。
- 例子：来源停止采集 → 历史仍可读取；制品缺失 → 明确不可采集，不删除历史解决状态问题。

### D10 迁移兼容

- 要求：现有订阅迁移保持原有来源行为及归档身份，等价条目不因迁移重复导入。
- 依据：已确认旧订阅和历史兼容性；现有统一 GUID/link/hash 去重与 source 标签已在研究中核查。
- 例子：已归档显式 RSSHub route 条目迁移后重启再采集 → 新增为 0、旧来源筛选不变；普通绝对 URL → 不从域名猜测新的模块归属。

### D11 状态真实性

- 要求：采集、加载与生命周期状态反映后台实际结果，失败不能伪装为正常空结果或完成。
- 依据：已确认完整生命周期与真实验收。
- 例子：仅修改磁盘活动指针、入口加载失败 → 不显示新版已加载；合法采集返回空批次 → 可以显示成功 0 条。状态字段见设计提案。

### D12 编辑兼容

- 要求：现有用户订阅的编辑和禁用结果不被预设更新覆盖。
- 依据：已确认旧订阅兼容性；现有来源管理提供用户编辑与启停。
- 例子：用户改展示名或停用订阅后更新预设目录 → 保留用户选择；新的预设 → 仅作为可选择的数据，不替用户启用。

### D13 实际运行形态

- 要求：源码、桌面、编译命令行和远程后台分别提供新模块接入的实际运行证据。
- 依据：已确认实际支持形态分别验收，以及研究中的目标支持矩阵。
- 例子：实际编译产物加载仓库外模块、采集并退出 → 可作为该形态证据；仅 Node 测试通过 → 不能替代编译产物证据。远程制品存在于后台，不在浏览器本机。

### 模块、接口与数据边界

核心拥有订阅、执行批准、调度、结果校验和唯一归档；来源生产者提供标准 feed 或转换后的新闻批次；RSSHub 服务运营者拥有服务运行与源站依赖。推荐的窄 worker ABI、本地完整制品、精确内容批准与独立服务 key 已获实施授权，实际接口见[设计说明](sdd.md)。

数据需要表达订阅、模块版本与内容身份、用户参数、新闻条目和后台状态；字段名、日期/正文格式、去重编码、存储布局与迁移版本见设计说明，不把研究里的示意类型当作现有 API。

## 测试决定

本节为随本 SRS 交审的测试层次建议，不声称已经执行：

- 导出函数与领域层：批准匹配、身份、参数校验、完整批次、去重及迁移；沿用仓内 Vitest 测试先例，不为本事项新增测试框架。
- 实际后台接口：配置和生命周期操作、来源状态、归档读取；使用受控本地 HTTP 输入，测试真实解析、转换和存储，而非回显模拟值。
- 实际模块宿主：仓库外制品加载、代码变化负对照、崩溃/卡死、在途切换和进程树停止；验证底层执行与退出，不只检查界面文字。
- 实际发布产物与远程后台：分别启动源码、桌面包、编译命令行入口；每种入口执行缺导出/错版本/缺依赖负对照；远程断开重连确认后台身份和结果。

边界对应 D1–D13，详细通过条件见独立小档测试计划。测试文件、命令选择、单项/全套/类型检查的执行次序属于第 5 阶段实施计划，不在这里虚构。

## 不在范围

- Alice 一键安装、托管或升级 RSSHub：主人明确选择用户或运营者提供实例。
- 安全执行未知恶意模块：主人选择可信代码批准与故障隔离，不作 OS 沙箱承诺。
- 合并 PR、发布版本或安装托管 RSSHub：不在本次交付授权内。
- 自动吸收或关闭 #1647、合并 #1767：事项及授权不同，保持独立。

自动下载、模块市场、自动更新和秘密委托未获本轮授权，不能据此扩张实施范围；其后续是否需要尚未决定，不把沉默解释为永久排除。
